# 产品一 · 技术架构

## 1. 架构原则

- 一份控制谱，多种消费者：编辑器、图谱渲染、TTS、播放器和后续评分共用同一数据契约。
- 原始事实与教学解释分离：字符时间戳、F0、能量等是证据；语势、焦点、教师口令是解释。
- 当前主界面只展示节奏、语势、表达焦点、停顿、拖音和句尾语调；教师口令、声音质感、置信度等继续留在底层。
- 图谱与 TTS 供应商解耦：Eleven/Fish/Qwen 都通过适配器读取统一控制谱。
- 生产内容版本化：草稿可以继续修改，已发布版本必须可复现、可回滚。
- 重型音频计算不放在 Web 边缘运行环境内。
- 朗诵知识库是系统能力，由分析服务默认读取；创作者不在单篇作品流程中选择文件或版本。

## 2. 组件划分

```text
创作端 / 观看端（React Web）
              │
              ▼
Web API 与发布服务（Cloudflare Worker）
     │            │             │
     ▼            ▼             ▼
 D1 结构化数据   R2 文件资产   异步任务编排
                                  │
              ┌───────────────────┼──────────────────┐
              ▼                   ▼                  ▼
      音频分析服务            LLM 控制谱服务      TTS 适配器
   对齐 / F0 / 能量 / 停顿      知识库 + 语义        Eleven v3
              │                   │                  │
              └───────────────────┴──────────────────┘
                                  │
                                  ▼
                      统一控制谱 + 音频时间轴
```

## 3. Web 产品层

- 技术：React + TypeScript，当前工程使用 vinext 运行并部署到 Sites。
- 创作端：作品信息与正文、参考朗诵、图谱直接编辑、AI 示范生成、发布预览。
- 观看端：三层图谱、AI 示范、整篇/单句播放、句子跳转和逐字高亮。
- API：作品、资产、控制谱版本、任务、TTS 候选、发布。
- D1：作品和版本化结构数据；R2：参考音频、系统知识库资产、AI 音频。

## 4. 当前页面流程

```text
准备作品
  作品名称 + 作者/来源 + 唯一正文 + 参考朗诵
      ↓ 解析参考朗诵（必须有音频）
编辑图谱
  三层图谱 + 当前句编辑面板
      ↓ 确认控制谱
生成示范
  控制谱 → TTS 提示词 → AI 音频 + 字符时间轴
      ↓
预览发布
  用户观看端只读取图谱 + AI 示范 + 时间轴
```

## 5. 音频分析层

建议作为独立 Python 服务或受控任务容器运行，因为音频解码、强制对齐、F0 和人声分离不适合 Cloudflare Worker。

流水线：

1. 解码与规范化（单声道、统一采样率、响度/削波检查）。
2. 可选人声分离与降噪；保留原文件和处理版本。
3. ASR + 给定正文强制对齐，生成字符级时间戳。
4. 提取停顿、时长、F0、能量、语速、谱倾斜等证据。
5. 系统默认检索内置朗诵知识库 v1.0。
6. 聚合为图谱句级特征，不直接把原始 F0 当作学习曲线。
7. 返回证据、置信度和低置信度区间。

候选技术：Whisper/Paraformer 转写，WhisperX/MFA/自研 CTC 对齐，librosa/pyworld/openSMILE 提取声学特征。最终选择以首篇真实音频的普通话对齐效果为准。

## 6. 控制谱生成层

输入：全文、体裁和背景、参考音频证据、知识库检索结果、表达预设。

处理顺序：

1. 全文级表达模式、基调和情感发展。
2. 划分图谱句。
3. 每句解释一个主要语势、句尾语调、焦点、停顿、拖音和声音质感。
4. 规则校验与自动修复。
5. 低置信度字段标记人工复核。

LLM 只输出规定 JSON；数据校验层拒绝自由文本和无效枚举。

## 7. 图谱渲染与对齐

每个字符/词拥有全文唯一 `index`。拼音和正文从同一 token 数组渲染为相同网格列；语势仅保存 `anchorStart`、`anchorEnd` 和强度。浏览器读取锚点文字真实位置后生成 SVG 曲线，字体加载、视口变化、缩放和容器尺寸变化都会重新测量。因此曲线位置不依赖固定像素，也不会与文字逐渐漂移。

## 8. TTS 层

```text
控制谱 JSON
    ↓
供应商无关的表演意图
    ↓
ElevenAdapter / FishAdapter / QwenAdapter
    ↓
Prompt + 音频 + 字符级时间戳 + 生成记录
```

Eleven v3 第一版规则：一句默认一个整体 Audio Tag，避免在中文字中间密集插标签导致语流破碎；短/长停结合标点和 `[short pause]`/`[long pause]`；Voice、Prompt、词典和结果一起版本化。

参考朗诵不会进入该生成链路并被覆盖。TTS 输出写入新的 `ai_demo` 音轨及独立时间轴；观看端只播放这个最终音轨。

## 9. 发布模型

- 编辑中的 Work 指向“当前草稿控制谱”。
- 发布动作创建不可变 PublicationRevision，固定控制谱版本、音频版本和时间轴。
- 观看端只读取 PublicationRevision，不读取编辑中的草稿。
- 撤回只改变发布状态，不删除历史资产。

## 10. 当前纵向切片与正式接入点

本轮先交付可运行的交互切片：示例控制谱、真实可播放的占位音频、编辑器、发布预览和同步播放器。正式接入点已经固定为：

- `AnalysisAdapter`：上传素材 → 控制谱初稿。
- `TtsAdapter`：控制谱版本 → 音频与时间轴。
- `WorkRepository`：作品与版本持久化。
- `AssetStore`：参考音频、系统知识库资产和生成音频。

真实素材和密钥到位后替换适配器，不需要重写图谱、编辑器和播放器。
